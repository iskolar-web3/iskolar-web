## Architecture

**iSkolar** is a scholarship management platform connecting students and sponsors, with Lumen API-based credential storage.

### Provider Stack (main.tsx → App.tsx)
```
StrictMode → HelmetProvider → TanStackQueryProvider → AuthProvider → RouterProvider
```
`AuthProvider` manages session state (access/refresh tokens in cookies). `TanStackQueryProvider` is defined in `src/integrations/tanstack-query/root-provider.tsx` and includes ReactQueryDevtools in dev.

### Routing
TanStack Router with file-based routes under `src/routes/`. Route groups:
- `_landing/` — public landing/marketing pages
- `_auth/` — login, register, email verification, password reset
- `_onboarding/` — role selection (Student/Sponsor) and profile setup
- `_student/` — student dashboard, discover scholarships, apply
- `_sponsor/` — sponsor dashboard, create/manage scholarships, review applicants
- `_admin/` — admin dashboard (metrics, signup timeline, student distribution) and user management; protected by `UserRole.Admin` check in route loader

`routeTree.gen.ts` is auto-generated by TanStack Router — do not edit manually.

### Data Flow
- **API calls** live in `src/lib/` organized by domain: `admin/`, `lumen/`, `user/`, `student/`, `sponsor/`, `scholarship/`, `school/`
- **Hooks** in `src/hooks/` expose React Query queries/mutations to components
- **Types** in `src/types/` define shared TypeScript interfaces
- There is no `src/services/` layer — hooks call lib functions directly via React Query

### Auth Flows
Beyond login/register, the following flows are implemented in `src/lib/user/`:
- **Email verification** — POST `/verify`, GET `/verify?token=`, POST `/verify/resend`
- **Password reset** — POST `/forgot-password`, GET `/reset-password?token=`, POST `/reset-password`

### Credentials (Lumen)
Credentials are uploaded to Azure Blob Storage via the Lumen API (`src/lib/lumen/`):
- `api.ts` — `createLumenFile()`, `getLumenFile()`, `computeFileChecksum()`
- `model.ts` — `LumenCreateParams`, `StoredCredential`, `LumenFileStatus` types
- `storage.ts` — localStorage wrapper for credential persistence

`useLumenCredentials()` hook (`src/hooks/useLumenFiles.ts`) polls every 15s (max 5 attempts) for upload status and syncs to localStorage.

Student profile shows the credentials section only when `VITE_ENABLE_LUMEN_CREDENTIALS=true`.

### IPFS Storage
Files (profile images, scholarship banners, application documents) are uploaded to IPFS via Pinata. Requires `VITE_PINATA_JWT` and `VITE_GATEWAY_URL` env vars.

### Utilities
`src/utils/` contains helpers for file validation (`fileHandling.utils.ts`, 10MB limit), file compression, fetch with timeout, form field handling, formatting, normalization, profile utilities, and Philippine phone validation (`phoneSchema.ts`).

## Environment Variables

```
VITE_BACKEND_URL=http://localhost:5000
VITE_PINATA_JWT=
VITE_GATEWAY_URL=
VITE_TEST_LUMEN_API_KEY=
VITE_TEST_LUMEN_API_SECRET=
VITE_BASE_URL=
VITE_SHOW_BETA_NOTICE=true
VITE_ENABLE_LUMEN_CREDENTIALS=true
```

### Feature Flags
- **VITE_ENABLE_LUMEN_CREDENTIALS** (true/false) — Controls visibility of student credentials section. Set to `false` to hide in test/staging environments.

## Code Style

- **Linter/Formatter:** Biome (tabs, double quotes) — run `bun check` before committing
- **Path alias:** `@/*` maps to `./src/*`
- **Strict TypeScript:** `strict: true`, `noUnusedLocals`, `noUnusedParameters`
- **UI components:** Shadcn/ui (style: new-york, base color: zinc) — add new components via `bunx shadcn@latest add <component>`

## Key Domain Concepts

**Application lifecycle:** Pending → Shortlisted → Approved/Denied → Granted

**Scholarship form fields** are dynamic with types: `short_answer`, `paragraph`, `multiple_choice`, `dropdown`, `checkbox`, `number`, `date`, `email`, `phone`, `file`

**User roles:** Student, Sponsor, Admin
